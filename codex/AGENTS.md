# 用户 Git 分支与云端推送约定

- Codex 建立的 `codex/` 前缀分支仅用于本地开发，不推送同名远端分支，也不通过其他分支名发布该开发分支。
- 用户明确说“推送云端”“push 到远端”等且本次任务与仓库明确时，默认授权：将本次已确认改动合并到本地 `main`，验证后仅推送远端 `main`。不为这条已授权流程重复请求确认；本地 commit 或确认开发分支本身不代表推送授权。
- 实际写远端的来源和目标必须都是 `main`，使用明确 refspec `refs/heads/main:refs/heads/main`，不使用裸 push、`--all`、`--mirror` 或将 `codex/...` 直接映射到远端 main。远端按用户指定或唯一可判定配置选择，多远端不明确时询问。
- 先检查 worktree 与工作区状态、fetch 远端 main，并核查本地 main 领先提交和待合入任务提交；不夹带其他任务或未授权提交。在已有 main worktree 安全操作，保护未提交内容；必要时创建隔离工作目录，不强制切换、reset、stash 或清理用户改动。
- 先同步远端 main，再将本次任务合入本地 main，按实际合并结果运行必要检查，再推送 main。保留逐需求提交历史，不擅自 squash/amend/rebase。仅推进可安全完成的部分。
- 有冲突、未知提交、缺少 main、权限/分支保护或远端竞态时报告具体阻塞，不强推、不绕过保护、不改推 codex/。并发更新可在重新核对后安全同步并重验；不能盲目反复推送。
- 分别核实并报告“已本地提交”“已合并 main”“已推送 main”，推送后确认远端 main 包含任务提交。该约定不授权额外发布操作或自动删除分支。
