# 用户 Git 分支与云端推送约定

- 开发默认使用 `codex/dev`：已有该分支时默认继续复用，并优先复用其所在工作目录；只有该分支不存在时才从 main 创建。不得因新需求、新任务、新聊天或分支已存在而另建分支。`codex/` 分支仅保留本地，不推送到远端，也不通过改名发布。用户明确指定其他分支时遵从其要求；既有授权足够时不为默认分支名重复确认。
- 复用前核对已有提交、未提交改动和 worktree 归属，保护已有工作；复用分支不等于授权提交或推送其他任务的改动。存在其他任务占用或无法安全处理的改动时先说明阻塞，不擅自另建 `codex/dev-任务标识` 等分支绕过，也不覆盖、重置或提前删除原分支。只有用户明确要求另开分支或隔离开发时才采用独立分支。
- 开发阶段保留逐需求本地提交。用户明确说“推送云端”“push 到远端”等且本次任务与仓库明确时，默认授权：将本次已确认批次的全部改动 squash 到本地 `main`，验证并生成一条汇总提交后仅推送远端 `main`。不重复确认这条已授权流程；本地 commit 或确认开发分支本身不代表合并或推送授权，仅授权本地合并时不推送。
- 实际写远端的来源和目标必须都是 `main`，使用明确 refspec `refs/heads/main:refs/heads/main`，并禁用自动跟随标签推送，例如 `git -c push.followTags=false push --no-follow-tags <远端> refs/heads/main:refs/heads/main`。不使用裸 push、`--all`、`--mirror` 或将 `codex/...` 直接映射到远端 main。远端按用户指定或唯一可判定配置选择，多远端不明确时询问。
- 先检查 worktree 与工作区状态、fetch 远端 main，并核查本地 main 领先提交和待合入任务提交；不夹带其他任务或未授权提交。在已有 main worktree 安全操作，保护未提交内容；必要时创建隔离工作目录，不强制切换、reset、stash 或清理用户改动。
- 先同步远端 main，再以 `git merge --squash <已核实任务tip>` 整合本次全部已授权改动，审查实际 diff 并运行必要检查，通过后正常 `git commit` 创建一条汇总提交，再推送 main。能快进时也采用 squash；多个开发分支仅在明确同属本次交付且全部获准时一起汇总。不压缩开发分支原始历史，不擅自 amend/rebase，不重写既有 main 历史。
- 合入 main 的汇总 commit 遵循中文 Conventional Commits，标题使用 `feat:`、`fix:`、`refactor:` 等实际类型。标题、正文及必要 footer 合计不超过 100 字；按字符计数，类型前缀、标点和空格计入，换行不计，提交前检查长度。优先用一句话概括核心成果，必要时补简短正文；保留必要的破坏性变更标记和说明。文件清单、测试过程及逐条提交明细留在任务记录，不塞进汇总消息。
- 有冲突、未知提交、缺少 main、权限/分支保护或远端竞态时报告具体阻塞，不强推、不绕过保护、不改推 codex/。并发更新可在重新核对后安全同步并重验；不能盲目反复推送。
- 分别核实并报告“已本地提交”“已 squash 合入 main”“已推送 main”，保存原始开发 SHA 与 main 汇总 SHA 的对应关系。推送后确认远端 main 包含汇总 SHA，不要求包含原始开发 SHA；squash 不建立原始开发提交与 main 的祖先关系。远端竞态后保留并安全同步已有汇总提交，不对同一批次重复 squash。该约定不授权额外发布操作。
- 本任务源分支的最终改动已完整合入本地 main 并验证通过后，自动安全删除该本地 `codex/` 分支，无需再次询问，不创建归档分支，也不以推送成功为前提。仅授权本地合并也适用；推送失败单独记录，继续从 main 重试，不重复 squash。尚未合并、仅部分合入、验证未通过或源分支新增未合并提交时保留。
- 删除前核实源 tip 与整合记录一致、main 当前保留全部改动，并保存源提交与汇总 SHA 的对应关系。Squash 后原 tip 通常不是 main 的祖先，需检查汇总 SHA、整合差异、源分支最终内容及验证记录，不能只凭祖先检查或提交消息判定覆盖。检查所有 worktree；有未提交/重要未跟踪或忽略文件、其他任务占用或归属不明时保留并报告。仅在本任务干净目录安全切到 main，或在 main 已被其他 worktree 检出时 detach 到已验证的 main 提交；保留目录和文件，不强制切换或清理。
- 确认分支未被任何 worktree 检出、tip 未变化且改动完整覆盖后，优先 `git branch -d <源分支>`。若仅因 squash 的祖先关系而拒绝，且内容核验及所有保护检查通过，可使用 `git branch -D <源分支>`；不以此绕过未合入内容或其他失败原因。删除后核实分支不存在、main 结果仍在，记录 `action=delete`、源分支/tip、汇总 SHA、覆盖依据和结果。不批量删除旧归档、其他任务分支或远端引用。
- 下一轮仅在 `codex/dev` 已不存在时从已核实的最新 main 创建同名分支；若仍存在，先按默认复用规则核对实际状态，不擅自另建、重置或提前删除。新任务本身不触发分支清理。
