# 合入 main 后推送云端

当用户明确发起推送云端命令时执行；此命令已授权本次任务合入本地 main 并推送 main，不重复询问。开发分支确认和自动本地 commit 本身不授权推送。`codex/` 分支仅用于本地开发，完整合入 main 并验证后可自动安全删除。

1. 确定本次任务、任务分支和提交清单，按用户指定或唯一可判定配置选择远端；多个候选不猜测。检查 `git worktree list` 与相关工作区状态。main 已被检出时使用其工作目录，不强制切换其他 worktree，也不自动 stash/清理无关编辑。
2. Fetch 选定远端并核实 main：只有远端 main 时可基于它建立本地 main；本地 main 与远端 main 均不存在时停止报告。没有可比较的远端 main 时，不擅自创建远端分支。必要时在干净的隔离 worktree 处理 main。
3. 核查本地 main 领先远端的提交，以及任务分支相对当前 main 的待合入提交。只纳入本次已确认任务；存在无法确认归属的提交先报告，不能因提交可达就自动推送其他人的本地工作。
4. 先同步远端 main；能快进则快进，分叉时仅在提交范围均明确且无业务歧义时正常 merge，保留历史。再将本次任务合入本地 main，能快进时允许快进，否则用正常 merge，消息遵循中文 Conventional Commits（如 `chore: 合并邮箱搜索需求到主分支`）。不自动 squash/rebase/amend。冲突需判断、远端保护等无法安全完成的问题停止说明。
5. 检查实际 main 结果，运行受整合影响的测试/构建，失败则不推送。记录任务 SHA、本地 main SHA、整合方式及检查结果，不用未整合任务分支的旧结果替代。
6. 再核查相对远端 main 的待推送提交范围，显式只推 main：`git push <已确认远端> refs/heads/main:refs/heads/main`。不使用默认 upstream 推送或 `--all`，不把任务分支直接映射到远端 main。
7. 查询远端 main，确认包含本次任务提交；核实的是推送时 main 的结果。若并发更新导致拒绝，重新 fetch、核对范围并安全整合/重验；不要强推或盲目重复，无解时保留本地结果报告。

## 已合并开发分支的清理

本次任务的本地 `codex/` 分支完整合入本地 main，且实际合并结果验证通过后，默认自动安全删除，无需再次确认。云端交付流程可在推送核实后执行此步骤；即使没有推送，只要已满足本地合并和验证条件，也可清理。推送失败不改变本地是否合入的事实，须分别记录。

- 仅处理本次任务分支。保存分支名和 tip SHA，显式运行 `git merge-base --is-ancestor <分支-tip-SHA> refs/heads/main` 确认完整合入；不能只依赖 `git branch -d` 的 upstream 判断。检查删除时分支 tip 未变，已合并的单个需求不代表整个开发分支均已合入。
- 检查 `git worktree list` 和对应目录状态。分支仍被检出时，仅在本任务干净且未被他人使用的 worktree 安全切换或 detach 到已核实提交后再删除，保留工作文件。存在未提交改动、重要未跟踪/忽略文件、其他任务占用或无法确认归属时保留分支并说明，不强制移除 worktree。遵守环境对 managed worktree 的操作要求。
- 使用 `git branch -d <本次codex分支>`，不用 `-D`。安全删除拒绝时说明原因，不绕过；不删除非 codex/ 分支、不批量清理其他任务、不删除远端分支。删除分支不清除需求记录、验收报告或提交历史。
- 记录 branch_cleanup（分支名、tip SHA、main SHA、结果及未清理原因），核实本地引用已不存在。分别报告本地提交、合入 main、远端 main 推送、分支清理和部署。main 已合入但 push 失败时明确说明，不自动回滚或改推 codex/ 分支。
